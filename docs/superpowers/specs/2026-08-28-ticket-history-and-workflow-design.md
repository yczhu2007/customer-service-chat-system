# 工单历史与处理体验改进设计

## 目标

在不扩大为独立工单平台的前提下，修复现有工单编辑、搜索和排序问题；增加状态操作历史，并在工单面板中展示既有会话转接带来的负责人变更。

## 范围

- 更新失败时仅在 HTTP 409 版本冲突后刷新，其他错误保留草稿。
- 实时工单事件不覆盖正在编辑的草稿，改为提示用户刷新。
- 工单状态选择仅提供当前状态和合法目标状态。
- 我的工单列表返回并显示工单编号；未解决工单优先，再按工单更新时间排序。
- 工单关键字使用字面包含匹配，`%` 与 `_` 不作为通配符。
- 新增工单状态历史：创建和每次实际状态变化分别记录操作人、原状态、目标状态和时间。
- 复用既有会话转接日志，在关联工单中显示负责人变更；不新增工单负责人字段或分派流程。

## 数据与接口

新增 `support_ticket_status_history`：`id`、`ticket_id`、`operator_id`、`from_status`（创建时为空）、`to_status`、`created_at`。`ticket_id` 外键关联工单，并建立 `(ticket_id, created_at, id)` 索引。

新增 `GET /chat/sessions/{sessionId}/ticket/history`。权限与工单详情一致：会话用户、当前负责客服和管理员可读。未创建工单返回空数组。

创建工单写入一条“创建：无 → 待处理”历史；仅状态发生变化时写入后续历史。描述或处理结果的修改不生成历史记录。

## 前端行为

工单面板在详情下展示最多 50 条状态历史和负责人变更。客服编辑中收到其他版本的实时通知时不自动替换表单，只显示“工单已有新版本，请刷新”。提供明确的刷新按钮。

客服工单列表显示 `TK-` 编号及状态。搜索结果按未解决优先和工单更新时间排序。

## 一致性与测试

状态历史与工单创建或状态更新放在同一数据库事务内。工单写入失败时历史必须回滚；通知仍在提交后发送。

补充单元测试覆盖历史创建、无状态变化不写历史、权限、草稿保护、409 刷新、状态可选项、编号展示与字面搜索。扩展现有可选真实基础设施测试，验证 MySQL 的唯一约束和版本条件更新。

## 非目标

不增加 SLA、提醒、独立工单分派、内部评论、工单附件、删除、独立管理员工单中心或新的前端依赖。
