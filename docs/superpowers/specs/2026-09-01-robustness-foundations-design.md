# 鲁棒性基础修复设计

## 目标

修复生产启动约束、前端请求超时、会话不可恢复删除和 MinIO 网络暴露四项风险；不改动 SQL 迁移管理和真实基础设施测试策略。

## 范围与约束

- 不新增依赖，不引入 Flyway、MySQL 容器或 CI。
- 现有数据库通过一份可重复执行的升级脚本新增会话逻辑删除字段。
- 删除会话不再删除消息、工单、评价或 MinIO 对象；管理员可恢复。
- 默认会话查询不返回已删除会话，管理员删除记录可通过专用筛选查看并恢复。
- 开发和生产均必须显式选择 Spring Profile；`dev` 保留本机默认连接参数，`prod` 只接受环境变量。
- 浏览器请求默认 15 秒超时，调用方可显式覆盖。
- MinIO API 和控制台仅映射到 `127.0.0.1`。

## 设计

### 1. 显式运行环境

新增启动校验组件：非测试环境若没有激活 `dev` 或 `prod`，立即终止启动。将当前开发默认值移动到 `application-dev.yml`；公共配置不再包含数据库、MinIO 凭据或本地 WebSocket Origin 默认值。`prod` 继续要求所有生产凭据与精确 Origin。

### 2. 前端请求超时

在唯一的 `request()` 入口创建 `AbortController`，15 秒后中止请求。调用方传入的中止信号会继续生效；仅由本地超时造成的中止转换为明确的中文错误，其余中止原因保持原样。

### 3. 会话逻辑删除与恢复

`chat_session` 增加 `deleted_at`、`deleted_by`。管理员删除接口改为记录这两个字段，不再调用会话结束、数据库级删除或对象存储删除。会话查询默认排除逻辑删除记录；管理端新增“已删除”筛选和恢复接口。恢复只清空删除字段，保留原始会话状态、消息、工单和附件。

### 4. MinIO 本机绑定

Compose 的 9000、9001 端口改为 `127.0.0.1` 映射。README 同步说明本机访问地址。

## 验收

- 未设置 Spring Profile 的应用启动失败；`dev` 与 `prod` 配置校验分别通过。
- 前端请求超过设定时间后抛出可读超时错误，外部取消仍保持取消语义。
- 管理员删除后会话默认列表不可见，消息、工单与附件记录仍在；恢复后再次可见。
- `docker compose ps` 中 MinIO 端口显示为 `127.0.0.1:9000-9001`。
- 后端、前端完整测试与前端构建均通过。
