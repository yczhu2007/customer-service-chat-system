# 管理端独立工单管理设计

**日期：** 2026-08-31  
**范围：** 将管理员“会话管理”中的工单查询能力迁为独立的“工单管理”页签；不改变客服端和用户端的工单处理流程。

## 目标与边界

- 管理中心侧边栏新增“工单管理”页签，保持在 `/admin` 内切换。
- 会话管理不再承担工单检索、统计或详情展示，仅保留“有关联工单”的只读标记。
- 管理员工单页只读：查询、筛选、查看详情、复制工单号、跳转关联会话；不提供管理员创建、修改、删除或状态推进。
- 客服端“我的工单 / 我参与过的工单”与用户端会话侧栏工单继续作为处理入口，保持不变。
- 不修改 `support_ticket` 表结构，不新增数据库迁移。

## 后端设计

新增管理员专用的工单查询能力，直接以工单为主表查询，而不是复用会话列表后在前端过滤。

- 分页接口：返回工单号、状态、优先级、分类、会话 ID/标题、用户、负责客服、创建时间和最近更新时间。
- 统计接口：使用与分页接口完全一致的筛选条件，按 `OPEN`、`IN_PROGRESS`、`WAITING_USER`、`RESOLVED` 返回全部匹配工单数量。
- 查询条件：关键词（工单号、会话标题、问题描述、处理结果）、工单状态、优先级、分类、负责客服、创建时间范围、页码和页大小。
- 默认排序：最近更新时间倒序。
- 两个接口均要求 `ADMIN` 角色；非管理员返回现有的权限拒绝响应。
- 工单详情复用既有按关联会话读取的工单服务。列表记录携带 `sessionId`，用于详情与关联会话跳转。

Mapper 层新增工单主查询、统计和分页计数；查询通过现有会话与用户关系补齐标题、用户和客服显示信息。现有会话查询接口不再接收管理员工单筛选参数。

## 前端设计

新增 `AdminTicketPanel` 并在 `AdminWorkspaceView` 注册“工单管理”页签。

页面组成：

1. 顶部状态统计卡：待处理、处理中、等待用户、已解决；数值对应当前筛选条件下的全部匹配结果。
2. 筛选栏：关键词、状态、优先级、分类、负责客服、创建时间范围、查询与重置。
3. 分页表格：工单号、状态、优先级、分类、会话标题、用户、负责客服、最近更新时间、操作。
4. 只读详情弹窗：展示工单号、状态、关联会话、负责人、问题描述、处理结果、更新时间；提供复制工单号与“查看关联会话”。

“查看关联会话”通过 `AdminWorkspaceView` 的共享 `sessionId` 状态切换到“会话管理”。会话管理接收该状态后筛选、高亮并滚动到对应行，随后清除定位状态，避免刷新时重复跳转。

会话管理移除以下工单 UI：工单状态统计、工单关键词/状态/仅有工单筛选、工单详情弹窗、工单操作按钮。会话表保留一列只读“关联工单”标记。

## 错误处理与权限

- 前端保留现有加载、空结果和请求错误提示模式。
- 非管理员无法调用管理员工单分页、统计接口。
- 关联会话不存在或不可定位时，显示已有的页面级错误提示，不保留失效高亮状态。
- 工单详情为空时显示“未找到工单”，不暴露内部数据或异常信息。

## 验证策略

- 后端：分页筛选与默认排序、统计与相同筛选条件一致、非管理员访问被拒绝。
- 前端：新页签切换、筛选参数与分页请求、统计展示、详情查看与复制提示、跳回会话管理后定位高亮。
- 回归：会话管理无工单详情/筛选/操作入口，只保留只读标记；用户端与客服端工单测试保持通过。

## 非目标

- 管理员工单增删改查或状态流转。
- 工单导出、批量处理、SLA、通知和自动分配。
- 将客服端或用户端工单功能改为独立页面。
