# Vue 3 Feature Completion Design

## Goal

补齐 Vue 3 工作台相对于 `stomp-test.html` 已有能力的缺口，同时保持现有 Spring Boot 接口和 STOMP 消息协议兼容。

## Scope

本次只补齐前端可见能力和必要的前端状态管理，不重写后端业务协议，不删除或修改 `stomp-test.html` 的现有功能。

### 1. 认证与账号

Vue 3 增加注册、忘记密码、重置密码、修改用户名、修改密码和恢复码页面。所有页面复用现有认证 REST 接口，成功后更新 Pinia 认证状态并回到登录或工作台页面；错误响应统一显示后端返回的中文错误信息。

### 2. 消息操作

聊天窗口增加历史消息“加载更多”，使用现有 `beforeMessageId`、`nextCursor` 和 `hasMore` 字段。消息操作区支持选择当前用户自己的文本消息、编辑和撤回；操作结果通过 `/user/queue/messages` 更新当前消息，并明确显示操作失败原因。已有自动 ACK 和自动已读逻辑保留，同时在消息元信息中显示保存、送达和已读状态。

### 3. 客服工作台

客服页面增加概况区域，展示在线客服、排队数、当前处理会话、今日关闭会话和满意度摘要；增加刷新入口和加载/错误状态。转接成功后刷新固定视图，并增加转接记录面板，展示来源客服、目标客服、操作时间和转接结果。

### 4. 管理员工作台

会话审计增加归档状态筛选和转接记录查看；会话行可展开查看基础会话信息和转接日志。管理员概况补充满意度摘要和客服负载列表。死信、VIP 技能组、角色权限和归档统计沿用当前页面，仅补充缺失的状态、刷新和空数据说明。

### 5. WebSocket 连接管理

在工作台状态区域增加连接、断开和重连状态。现有 STOMP 客户端增加连接状态回调、重连次数、心跳活动时间和错误队列状态；页面提供可读的连接日志和错误提示。自动重连不改变现有订阅地址，重复连接前先释放旧客户端。

## Data Flow

认证页面调用 REST 接口并写入 `auth` store；工作台进入后由 `chat` store 建立 STOMP 连接并订阅 `/user/queue/chat`、`/user/queue/messages` 和 `/user/queue/errors`。历史消息、消息编辑/撤回、已读和 ACK 都通过现有 `/app` 目的地发送。管理员和客服统计、转接记录继续通过现有 REST API 获取。

## Error Handling

- REST 错误统一经过现有 `http-client` 转换为可读消息。
- STOMP 错误记录在连接状态区域，不覆盖当前聊天内容。
- 自动重连最多连续尝试 5 次；每次重连使用递增等待时间，超过次数后显示“请手动重连”。
- 消息操作失败时保留原消息内容，并显示失败原因。
- 空列表显示明确的业务说明，例如“当前没有未读会话”“暂无转接记录”，不显示原始接口路径或内部 ID。

## Acceptance Criteria

1. 用户可以在 Vue 3 页面完成注册、登录、忘记密码、重置密码和账号资料修改。
2. 用户或客服可以加载更早历史消息，并对自己发送的文本消息编辑或撤回。
3. 客服可以看到概况、满意度摘要和转接日志。
4. 管理员可以按归档状态查询会话，并查看会话转接记录和客服负载。
5. WebSocket 断开后页面显示状态并支持重连，错误不会只出现在浏览器控制台。
6. 现有文本、图片、文件、排队、重新咨询、归档、评价、快捷回复、角色权限和固定客服视图继续可用。
7. 前端单元测试覆盖新增交互，后端依赖模块编译成功，最终打包后的 `/frontend/index.html` 返回 HTTP 200。

## Non-Goals

- 不新增第三方 UI 框架。
- 不改变后端 REST 路径、STOMP 目的地或数据库结构。
- 不把 `stomp-test.html` 删除或改造成 Vue 页面。
- 不实现超出 `stomp-test.html` 和当前技术文档范围的 CRM 功能。
